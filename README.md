# SkillLens -- AI-Powered Placement Readiness Analysis

## 1. Project Overview

SkillLens is a machine-learning web application that estimates a student's
placement readiness from structured academic, coding, project, experience,
and soft-skill data. It returns a 0-100 readiness score, a 4-category
readiness label, an explanation of the major factors behind the prediction,
a what-if simulator, single-student and CSV batch prediction, and an
analysis dashboard.

**This is an academic portfolio project built on synthetic data.** No
result, metric, or chart in this repository is fabricated -- every number
comes from the actual trained model evaluated on real (synthetic) held-out
data. See `AI_USAGE.md` for how AI assistance was used and verified.

## 2. Problem Statement

Students often have no single, data-driven view of how "placement ready"
they are across the many dimensions recruiters actually evaluate
(academics, DSA/coding, projects, experience, soft skills). SkillLens
turns those inputs into one interpretable score and explains *why*.

## 3. Objectives

- Predict a readiness category and continuous score from structured
  student data.
- Explain every prediction (global + individual factors).
- Let a user interactively explore "what if I improved X?".
- Support both single-student and CSV-batch use.
- Do all of this transparently: real metrics, documented assumptions,
  documented limitations.

## 4. Dataset Description

`data/raw/students.csv` -- **3,000 synthetic students**, generated by
`src/generate_dataset.py`. It does **not** represent real placement
outcomes; distributions and the target-generation formula are fully
documented in that file's docstrings. ~3% missingness is intentionally
injected into 4 columns to exercise robustness handling.

An audit-only column, `_audit_true_latent_score`, stores the hidden
continuous score used to build the category label. It is **never** used
as a model feature -- it exists solely to support the failure analysis
(Step 11 / `reports/failure_analysis.md`).

## 5. Feature Description

23 raw features across 6 groups -- see the table in `src/predict.py`'s
`RAW_FEATURE_COLS` and the full description in `src/generate_dataset.py`:
Academic (cgpa, 10th/12th %, backlogs), Coding/DSA (LeetCode solved,
contest rating, DSA proficiency), Technical (languages known, DBMS/OOP/OS/CN
scores), Projects (count, ML project count, GitHub commits), Experience
(internship flag + duration), Placement skills (aptitude, communication,
resume, interview prep), Other (certifications, extracurriculars).

## 6. Data Preprocessing

One reusable `sklearn.compose.ColumnTransformer` (`src/data_preprocessing.py`):
median imputation (robust to outliers) + standard scaling for numeric
features; a categorical branch with `handle_unknown="ignore"` exists for
extensibility, though v1 has no string categoricals. Fitted **only on the
training split**, then applied identically everywhere else (validation,
test, the app, CSV batch, and what-if) -- this is the project's core
anti-leakage guarantee.

**Split:** fixed, stratified 70/15/15 train/validation/test
(`src/data_preprocessing.py`), with an explicit assertion that the three
splits share no row indices.

## 7. Model Architecture

Two models were trained and fairly compared on the same untouched test set:
- **Baseline:** Logistic Regression (`src/train.py`)
- **"Stronger" candidate:** Random Forest (`src/train.py`, tuned in
  `src/tune.py` via `GridSearchCV` scored on the validation fold only)

## 8. Model Comparison

| Model | Accuracy | Macro F1 |
|---|---|---|
| Logistic Regression (untuned baseline) | 0.698 | 0.711 |
| Random Forest (untuned) | 0.540 | 0.458 |
| Random Forest (tuned) | 0.580 | 0.586 |
| **Logistic Regression (tuned) -- FINAL** | **0.707** | **0.724** |

**Logistic Regression was chosen as the final model** -- it genuinely
outperforms tuned Random Forest on this dataset, on both accuracy and
macro-F1. This is a real, checked result (see `reports/evaluation_report.md`
and the "why" behind it), not a default choice, and it happens to also be
the more interpretable model.

## 9. Evaluation Metrics

Full numbers, confusion matrices, and per-class precision/recall/F1 are in
`reports/evaluation_report.md`, generated by `src/evaluate.py`. Metric
definitions (accuracy, macro precision/recall/F1) are written there in
plain language for viva use. ROC-AUC is not reported: this is a 4-class
(not binary) problem, per the brief's own guidance.

## 10. Explainability

`src/explain.py`, Step 7:
- **Global:** permutation importance (mean macro-F1 drop when a feature is
  shuffled) -- model-agnostic and honest about what actually matters to
  real performance. See `reports/figures/08_global_importance.png`.
- **Individual:** feature-ablation against the continuous **readiness
  score** (not a single class's log-odds) -- swap a feature for the
  population median, recompute, take the difference. This is what makes
  "increased/decreased readiness" mean the same thing regardless of which
  category a student lands in. SHAP is used automatically if installed;
  otherwise this ablation method is the fallback (both are documented in
  `explain.py`).

## 11. Dashboard

`app/app.py`, "Dashboard" tab (Step 10): summary cards (students analyzed,
avg score, placement-ready %, avg CGPA, avg DSA), category/score
distributions, CGPA/DSA/projects/internship vs. readiness charts, global
feature importance, and filters (category, CGPA range, DSA range,
internship status).

## 12. What-If Analysis

`app/app.py`, "Single-Student Prediction & What-If" tab (Step 8). Change
any input, see the score/category update live, plus a **"what changed
since your last edit"** table attributing the score change to the specific
inputs you just moved. Built entirely on `src/predict.py`'s single
canonical scoring function, so it can never drift from the CSV/dashboard
numbers. Clearly labeled as a simulation, not a guarantee.

## 13. CSV Prediction

`app/app.py`, "CSV Batch Prediction" tab (Step 9), backed by
`src/csv_validation.py` (unit-tested in `tests/test_app_logic.py`).
Validates required columns, handles missing/invalid/extra columns and
text yes/no values, never crashes, and produces a downloadable CSV with
`predicted_category`, `readiness_score`, and per-class probabilities
appended.

## 14. Failure Analysis

`reports/failure_analysis.md` (Step 11, `src/failure_analysis.py`)
examines the 20 lowest-confidence wrong test-set predictions using the
audit-only hidden latent score. Headline finding: **100% of errors are
adjacent-category misses** (never confuses opposite extremes) and **37%
are genuine boundary cases** (true score within 2.5 points of a bin edge)
-- evidence the errors are structurally reasonable, not random noise.

## 15. Testing

`tests/` (Step 13), 19 tests across three files, runnable with one
command:

```
pytest
```

- `test_preprocessing.py` -- pipeline fitting, missing-value handling,
  scaling correctness, reusability on new data.
- `test_prediction.py` -- model loading, valid/extreme/missing-value
  predictions, missing-column error handling, batch prediction.
- `test_app_logic.py` -- CSV validation: empty file, missing columns,
  extra columns, bad text values, text yes/no normalization, mixed-issue
  batches.

(Note: `shap` and `streamlit` were not installable in the sandboxed
environment used to build this project offline; the test suite and all
non-Streamlit scripts were verified directly. Run `pytest` yourself after
`pip install -r requirements.txt` to confirm in your own environment.)

## 16. Limitations

- Trained entirely on **synthetic** data with a documented but still
  artificial target-generation formula -- real placement outcomes involve
  factors (interview performance on the day, company-specific criteria,
  market conditions) this model cannot see.
- ~29% test-set error rate; category boundaries are inherently fuzzy for
  students near a cutoff (see failure analysis).
- No causal claims: a factor "contributing positively" describes
  association learned by the model, not a guarantee that changing it
  changes real outcomes.
- Currently only numeric/binary features; no true categorical (e.g.
  branch, college tier) features yet.

## 17. Future Improvements

- Add real (anonymized, consented) placement outcome data if available.
- Add categorical features (branch, college tier) to exercise the
  one-hot branch of the preprocessing pipeline.
- Try Gradient Boosting / XGBoost with stronger regularization to see if
  it can beat Logistic Regression once properly tuned.
- Add SHAP-based waterfall plots in the app when `shap` is available.

pip install -r requirements.txt

## 19. How to Run

```
# Regenerate the synthetic dataset
python src/generate_dataset.py --n 3000 --seed 42

# Exploratory analysis (script or notebook)
python src/eda.py
# or open notebooks/exploratory_analysis.ipynb

# Preprocessing + train/val/test split
python src/data_preprocessing.py

# Train baseline + stronger model
python src/train.py

# Tune the Random Forest, then the final Logistic Regression
python src/tune.py
python src/tune_logreg.py

# Evaluate all models on the untouched test set
python src/evaluate.py

# Explainability (needs src/ on the path for cross-imports)
PYTHONPATH=src python src/explain.py

# Failure analysis
PYTHONPATH=src python src/failure_analysis.py

# Run the web app
streamlit run app/app.py

# Run the automated tests
pytest
```
