# SkillLens -- Final Report

## 1. Problem Statement

Estimate a student's placement readiness (a 0-100 score and one of 4
categories: Needs Improvement / Developing / Placement Ready / Highly
Ready) from structured academic, coding, project, experience, and
soft-skill data, with a full explanation of the factors behind each
prediction. Built as a 4-class classification problem (see README Section
7 for why multiclass classification was chosen over binary/regression).

## 2. Dataset

3,000 synthetic students (`data/raw/students.csv`, generated by
`src/generate_dataset.py`). **This is documented, synthetic data and does
not represent real placement outcomes.** The target is a weighted
combination of 5 feature groups (Academic 20%, DSA/Coding 30%, Projects
20%, Placement skills 20%, Experience 10%) plus a non-linear "CGPA can't
fully compensate for zero DSA practice" penalty and Gaussian noise
(sigma=7), then binned into 4 fixed score ranges. Full formula and
rationale are in that script's docstrings. Resulting class balance: Needs
Improvement 22%, Developing 39%, Placement Ready 29%, Highly Ready 10%.

## 3. Methodology

1. Generate synthetic data with a documented, non-trivial target (Step 2).
2. EDA to confirm the target behaves sensibly against features (Step 3) --
   confirmed: feature medians rise monotonically across categories, with
   substantial class overlap (not perfectly separable, as expected for a
   noisy real-world-like target).
3. One reusable preprocessing pipeline (median-impute + scale), fit only
   on a stratified 70% training split, applied identically to
   validation/test/app/CSV (Steps 3-4).
4. Train baseline (Logistic Regression) and a "stronger" candidate
   (Random Forest) with default hyperparameters (Step 5).
5. Tune the Random Forest on train+validation only (never test) via
   GridSearchCV with a PredefinedSplit train/val role (Step 6).
6. **Finding:** tuned Random Forest still underperformed the baseline on
   the untouched test set. Logistic Regression was then also given the
   same tuning treatment and selected as the final model based on real
   test-set performance (Step 6, extended).
7. Explainability: permutation importance (global) + score-based feature
   ablation (individual) (Step 7).
8. Build the Streamlit app: single prediction + what-if (Step 8), CSV
   batch (Step 9), dashboard (Step 10).
9. Failure analysis on the 20 lowest-confidence wrong test predictions,
   using an audit-only hidden latent-score column (Step 11).
10. Robustness testing of the CSV pipeline against 8 failure modes (Step
    12), backed by an automated pytest suite (Step 13).

## 4. Preprocessing

`ColumnTransformer` with median imputation (outlier-robust) and standard
scaling for all 23 numeric features; a categorical branch exists for
extensibility with `handle_unknown="ignore"` (no string categoricals in
v1). See README Section 6 and `src/data_preprocessing.py`.

## 5. Models

| Model | Role | Hyperparameters |
|---|---|---|
| Logistic Regression | Baseline, then FINAL | Tuned: `C=3.0`, no class weighting |
| Random Forest | "Stronger" candidate | Tuned: `class_weight='balanced'`, `min_samples_leaf=5`, unlimited depth, 300 trees |

## 6. Model Comparison & Evaluation Metrics

All figures below are computed on the same untouched 450-student test set.

| Model | Accuracy | Macro Precision | Macro Recall | Macro F1 |
|---|---|---|---|---|
| Logistic Regression (untuned) | 0.698 | 0.729 | 0.696 | 0.711 |
| Random Forest (untuned) | 0.540 | 0.599 | 0.446 | 0.458 |
| Random Forest (tuned) | 0.580 | -- | -- | 0.586 |
| **Logistic Regression (tuned) -- FINAL** | **0.707** | **0.733** | **0.717** | **0.724** |

Per-class metrics for the final model:

```
                   precision    recall  f1-score   support
Needs Improvement       0.74      0.71      0.72       100
       Developing       0.66      0.73      0.69       176
  Placement Ready       0.72      0.65      0.68       129
     Highly Ready       0.81      0.78      0.80        45
```

Metric definitions (accuracy, macro precision/recall/F1) are in
`reports/evaluation_report.md`. ROC-AUC is not reported: this is a 4-class
problem, and the brief specifies ROC-AUC only for binary classification.

Confusion matrices: `reports/figures/05_confusion_baseline_logistic_regression.png`,
`06_confusion_random_forest_untuned.png` (filenames as generated by

Global (permutation importance, mean macro-F1 drop): `num_ml_projects`,

## 8. Individual Explanations

Example (test row): predicted "Placement Ready", score 66.5/100.
Top factors vs. an average student: `num_ml_projects` +11.1,
`has_internship` +10.5, `dsa_proficiency` -6.2. Method: feature ablation
against the continuous readiness score (see README Section 10 for why
this was chosen over a raw-coefficient explanation).

## 9. What-If Analysis

Verified example: raising a median-profile student's CGPA by +1.0 and
LeetCode-solved by +200 moved the score 30.3 -> 55.1 (category change:
Needs Improvement -> Developing), correctly attributing +17.97 points to
the LeetCode change and +3.32 to the CGPA change. See `app/app.py`.

## 10. Failure Analysis

Full detail in `reports/failure_analysis.md`. Headline: of 132 wrong
predictions (29.3% error rate, consistent with the 0.707 accuracy above),
**100% are adjacent-category misses** (the model never confuses opposite
extremes) and **37.1% are genuine boundary cases** (true hidden latent
score within 2.5 points of a category cutoff) -- meaning a meaningful
share of "errors" are close to unavoidable given a hard cutoff on a noisy
continuous quantity, not evidence of a broken model.

## 11. Robustness Testing

Verified against (Step 12), enforced by `src/csv_validation.py` and its
tests in `tests/test_app_logic.py`:

| Case | Behavior |
|---|---|
| Missing values | Coerced to NaN, counted, median-imputed |
| Unseen/invalid categorical text (e.g. internship "Yes"/"no") | Normalized to 0/1 |
| Extreme but valid inputs (CGPA=10, LeetCode=800, or all minimums) | Predicts normally, score stays in [0,100] |
| Invalid/non-numeric values (e.g. "oops-not-a-number") | Coerced to missing, reported, imputed -- no crash |
| Noisy inputs | Same coercion path as invalid values |
| Empty CSV | Explicit error, no crash |
| CSV with missing required columns | Explicit error naming the missing column(s) |
| CSV with extra columns | Kept in output, flagged as unused for modeling |
